## ภาพก่อน/หลัง (`.ba`)
- 2 ชั้นซ้อน · ชั้น "หลัง" ตัดด้วย `clip-path: inset(0 0 0 var(--x))` · เส้นแบ่ง 2px สี surface + ปุ่มจับวงกลม 40 เงา elevation-2
- ป้าย "ก่อน" / "หลัง" มุมบน (pill surface 88%) · ลาก กด หรือใช้คีย์บอร์ดผ่าน `<input type="range">` ที่ซ้อนอยู่ (มองไม่เห็นแต่โฟกัสได้ · วงโฟกัสอยู่ที่ปุ่มจับ) · `aria-valuetext` บอกสัดส่วน
- ภาพจริงทั้งสองต้องขนาดและมุมกล้องเดียวกัน

## บล็อกที่เลือกใส่ได้ (แต่ละโปรเจกต์ไม่เหมือนกัน)
ข้อมูลโปรเจกต์ = `{title, cat, tags[], role, scope[], time, team, chapters:[{t, b:[block…]}]}` · บทและบล็อกเลือกเอง ลำดับเอง

| บล็อก | ใช้เมื่อ | หน้าตา |
|---|---|---|
| `p` | ข้อความปกติ | ย่อหน้า 15 ink ≤ 62 ตัวอักษร |
| `tbd` | ยังไม่มีข้อมูลจริง | ข้อความ text-2 + ป้าย "รอข้อมูลจริง" |
| `steps` | **วิธีทำงานเฉพาะโปรเจกต์** (เลือกขั้นเอง เช่น UX ล้วน: Plan → Interview → Synthesize · Frontend: Plan → Build → Ship · AI: Understand → Prompt → Design → Evaluate) | เส้นเวลาแนวนอนแบบคงที่ (มือถือแนวตั้ง) |
| `out` | งานที่ส่งมอบ | ชิปพื้น muted |
| `quote` | คำพูดผู้ใช้จริง (ขออนุญาตแล้ว) | เส้นซ้าย 3px ตัว 17 |
| `image` | ภาพหน้าจอ/ภาพประกอบ | 16:9 มุม 16 + คำบรรยาย |
| `ba` | ภาพก่อน/หลัง | component `.ba` ลากเทียบ |
| `video` | วิดีโอสาธิต (YouTube / Vimeo / MP4) | ปุ่มเล่นบนปก · **โหลดวิดีโอเมื่อกดเท่านั้น** · คำบรรยายใต้ |
| `links` | Figma prototype · GitHub · เว็บจริง | การ์ดลิงก์ ไอคอน + ชื่อ + ที่มา + ↗ · เปิดแท็บใหม่ (บอกผู้อ่านหน้าจอ) |
| `callout` | สิ่งที่ตัดทิ้ง / ข้อจำกัด | กล่องพื้น muted มุม 16 |
| `stats` | ผลลัพธ์เป็นตัวเลข **จริงเท่านั้น** | ตัวเลข 26/500 + คำอธิบาย · ไม่มี = "—" + รอตัวเลขจริง |
| `ai` | **งานที่ใช้ AI**: AI ทำอะไร · คนทำอะไร · เครื่องมือ · กันพลาด | ตาราง 2 คอลัมน์ เส้นคั่น |
| `prompt` | ตัวอย่างคำสั่ง / flow ของ AI | กล่องตัวอักษร monospace + ปุ่ม "คัดลอก" (ล้มเหลว = "คัดลอกไม่ได้") |

- งาน AI ต้องบอกชัดว่า**คนตรวจตรงไหน**และ**กันพลาดอย่างไร** · ไม่ทำหน้าจอแชตปลอม ใช้วิดีโอหรือภาพจริง
- ตัวอย่างใน preview: UX/UI ครบ · UX อย่างเดียว · Frontend + วิดีโอ · มี AI

## ผลงานที่ยังไม่มีเนื้อหา case
- ทุกการ์ดผลงานกดเข้าหน้า case ได้ · งานที่ยังไม่มีเนื้อหา ลิงก์เป็น `case.html?t=ชื่อ&c=หมวด&y=ปี&tags=…` แล้วหน้า case สร้างโครงจากค่าที่ส่งมา (หัว + แท็ก + 4 บท: โจทย์ · วิธีทำงาน · ทางแก้ · ผลลัพธ์) ทุกช่องเป็นป้าย "รอข้อมูลจริง" (decisions #97)
- มีเนื้อหาแล้ว: เพิ่มโปรเจกต์ใน `P` ของ `case.html` และชื่อใน `CASEMAP` ของหน้าแรก/หน้า work

## ความจริงของเนื้อหา
- ผลลัพธ์ใช้ตัวเลขจริงเท่านั้น · ยังไม่มี = ป้าย "รอตัวเลขจริง" หรือเขียนสิ่งที่เปลี่ยนจริง ห้ามตัวเลขสมมติ
- คำพูดผู้ใช้ต้องเป็นของจริงและขออนุญาตก่อน
- **เนื้อหาที่ยังแต่งขึ้น (ชื่อโปรเจกต์ ระยะเวลา ทีม เรื่องปัญหา) ต้องมีป้าย "ข้อมูลตัวอย่าง · แก้เป็นของจริง"**: หน้าแรกติดใต้หัว "Case study" · หน้าเต็มติดท้ายบรรทัด "Case study · หมวด" (ขึ้นเองทุกโปรเจกต์ที่ยังไม่มี `real: true` ในข้อมูล) · ใส่ของจริงครบแล้วตั้ง `real: true` ป้ายหายเอง

## ทำต่อภายหลัง: หลังบ้านแก้หน้าเอง
- ข้อมูลโปรเจกต์เก็บเป็นบล็อกอยู่แล้ว → ต่อกับหลังบ้านแบบ **ลากวางบล็อก** (เพิ่ม/ลบ/สลับบท · เลือกชนิดบล็อก · อัปโหลดภาพ/วิดีโอ · เลือกขั้นตอนการทำงาน) แล้วหน้าเว็บแสดงตาม
